## Overview

AllergenesChecker.nl helps users identify allergens and E-numbers found in food ingredients. It is intended for consumers as well as horeca professionals who need a straightforward way to check ingredient information without configuring a backend or maintaining a complex application stack.

The application is published as a static website and works with ordinary web hosting. Its HTML and JavaScript foundation provides quick searches, direct access to the information, and a small, easy-to-deploy project that can be maintained without a build pipeline.

## What It Includes

- Instant search for finding ingredients
- Ingredient scanner for reviewing food labels and ingredient lists
- Reference data covering more than 150 E-numbers
- Summary of the 14 EU allergens
- Separate information page for horeca users
- Static HTML and JavaScript structure with no build step
- No package dependencies to install

## Using the Checker

Launch the website in a browser and enter an ingredient, allergen, or E-number in the search box.

A common way to use the site is:

1. Enter a search term in the live search field.
2. Inspect the information returned for the related ingredient or E-number.
3. Use the scanner and overview sections for larger ingredient lists.
4. Open the horeca page for information intended for food-service situations.

## Frequently Asked Questions

**How can I refresh the data?**  
Modify the embedded data and site content, then publish the updated static files again.

**Does the checker need a backend?**  
No. It is built as a static website and does not need a server for normal operation.

**Where are interface changes made?**  
Edit the HTML and JavaScript source files included in the repository.

**Why might the search return no results?**  
Verify that the data files exist, confirm that the scripts load correctly, and check whether the browser is restricting access to local files.

**Do I need to complete a separate installation?**  
No. Place the files on a static web host, or open them locally when testing; no additional setup flow is required.
